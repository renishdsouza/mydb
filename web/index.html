Project Summary

This site is a complete web companion for your NITCbase codebase. It does not edit or run the native disk files used by the C++ implementation. Instead, it uses an in-browser virtual disk snapshot, persisted with IndexedDB, so users can test workflows safely.

Core Modules

  • FrontendInterface: parses SQL-like commands
  • Schema: relation and attribute catalog management
  • Algebra: select, project, join and insert logic
  • BPlusTree: index creation, search and split operations
  • Buffer and Disk: block IO and persistence behavior

Disk Model in Native Build

  • Disk size: 16 MB
  • Block size: 2048 bytes
  • Total blocks: 8192
  • Runtime copy model: disk to disk_run_copy on start, reverse on graceful exit

Browser Workaround

  • Virtual disk image in IndexedDB, never writes host disk files
  • Serializable state export or import for sharing sessions
  • Subset SQL runtime supports CREATE, INSERT, SELECT, JOIN and schema updates

Architecture Mapping

The diagram maps the native C++ layers and the browser sandbox adaptation.

Native Pipeline

  1. FrontendInterface::handleFrontend
  2. Frontend APIs route commands to Schema and Algebra
  3. Schema and Algebra call BlockAccess and BPlusTree
  4. Buffer mediates Disk::readBlock and Disk::writeBlock
  5. Disk constructor and destructor copy session state

Browser Pipeline

  1. Command parser reads SQL-like text from console
  2. JS execution engine updates table metadata and rows
  3. IndexedDB stores virtual disk snapshot and op-log
  4. No direct file rewrite calls to local machine filesystem
  5. Optional snapshot download for backup or report attachment

Command Reference

The playground follows command styles from your RegexHandler definitions.

DDL

CREATE TABLE Students (id NUM, name STR, cgpa NUM);
OPEN TABLE Students;
CLOSE TABLE Students;
ALTER TABLE RENAME Students TO Learners;
ALTER TABLE RENAME Learners COLUMN cgpa TO gpa;
CREATE INDEX ON Learners.id;
DROP INDEX ON Learners.id;
DROP TABLE Learners;

DML

INSERT INTO Students VALUES (1, Alice, 9.2);
SELECT * FROM Students INTO StudentsCopy;
SELECT id, name FROM Students INTO NameList;
SELECT * FROM Students INTO Toppers WHERE cgpa >= 9.0;
SELECT name FROM Students INTO HighCGPA WHERE cgpa > 8.5;
SELECT * FROM Students JOIN Marks INTO Combined
WHERE Students.id = Marks.id;

GitHub Pages Deployment

  1. Build WASM artifacts by running ./wasm/build_wasm.sh from repository root.
  2. Push this repository to GitHub.
  3. Open repository Settings, then Pages.
  4. Set Source to Deploy from a branch.
  5. Select branch main and folder web or root based on your publish strategy.
  6. Save, then open the generated github.io URL.

If you publish from root, keep this site under the web folder and configure Pages to use that folder.
